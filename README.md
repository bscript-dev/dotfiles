# dotfiles

Zsh configuration kept in a repo and linked into `$HOME` with symlinks — the
pattern described at <https://dotfiles.github.io>.

**Rule of this repo: only what works correctly on both macOS and Linux.**
Nothing tied to a specific OS, a specific machine, or holding a secret. Every
external tool is loaded behind a guard — a missing nvm, jenv or gcloud does not
break the shell, that section simply does not run.

## Install

```bash
git clone <repo-url> ~/dotfiles
cd ~/dotfiles
./install.sh --dry-run   # see what would happen first
./install.sh
```

The script is idempotent. Existing real files are moved to
`~/.dotfiles-backup/<timestamp>/` — nothing is overwritten silently.

On a fresh Linux box it also installs `zsh`, `git` and `curl` if they are missing
and sets zsh as the login shell — but only when it can become root **without a
password** (running as root, or passwordless `sudo`). It never prompts: a bootstrap
that blocks on a password hangs a workspace provisioner. When it cannot, it prints
the exact command to run by hand. Pass `--no-shell` to leave the login shell alone.

### Remote workspaces (Coder, Codespaces)

Paste the **repository** URL into the dotfiles field — not a link to `install.sh`:

```
https://github.com/<user>/dotfiles
```

Coder clones the repo and runs the first match out of `install.sh`, `install`,
`bootstrap.sh`, `bootstrap`, `script/bootstrap`, `setup.sh`, `setup`,
`script/setup`. This repo ships `install.sh`, first on that list, and it is
committed with mode `100755` — an executable bit is a hard requirement there.

The script is ordered for exactly this case: **symlinks are created before
anything touches the network**, and every download is non-fatal. A workspace with
a blocked registry still gets your `.zshrc`, `PATH` and functions; it just misses
the prompt theme. `.zshrc` skips Oh My Zsh when it is not there instead of erroring
on every prompt.

Two more things decide whether it *looks* right:

- **Nerd Font** — required by the prompt. What matters is the font of the terminal
  emulator, not the machine: over SSH from a Mac the local font is used, so it
  already works. On an Ubuntu desktop install MesloLGS NF into
  `~/.local/share/fonts/`, run `fc-cache -fv`, and select it in the terminal profile.
- **Network on the first prompt** — Powerlevel10k downloads its `gitstatusd` binary
  for the current platform on first run. Without it you get
  `gitstatus failed to initialize` and no git segment.

On servers, also make sure the locale is `*.UTF-8` and not `C`/`POSIX`, or the
icons break regardless of the font.

## What is in the repo

| File | Symlink in `$HOME` | What it is |
|---|---|---|
| `zsh/.zshrc` | `~/.zshrc` | Oh My Zsh, p10k theme, 10 plugins, conditional nvm / jenv / gcloud, `b_dcls` and `b_graph` functions |
| `zsh/.p10k.zsh` | `~/.p10k.zsh` | Powerlevel10k prompt appearance (generated by `p10k configure`) |
| `install.sh` | — | Bootstrap: packages, symlinks, Oh My Zsh, p10k, two zsh plugins, login shell |
| `zsh/.zshrc.local.example` | — | Template for OS-specific paths (Homebrew, JetBrains) |
| `.npmrc.example` | — | Template for the npm token |

The repo carries **no personal data at all** — no name, no email, no hostname,
no credentials.

Note that files starting with a dot are hidden: `ls` and Finder show `zsh/` as
empty. Use `ls -la`, or `Cmd`+`Shift`+`.` in Finder.

### What `.zshrc` actually does

| Section | Portable because... |
|---|---|
| p10k instant prompt | Pure zsh, cache under `$XDG_CACHE_HOME` |
| Oh My Zsh + theme | Installed by `install.sh` on both systems, and skipped by a guard when the install failed |
| Plugins: `git`, `colored-man-pages`, `colorize`, `pip`, `python`, `zsh-syntax-highlighting`, `zsh-autosuggestions`, `ng`, `yarn`, `docker` | Aliases and completions only, no macOS-only commands |
| nvm | Checks `~/.nvm/nvm.sh` (installer, both systems), then `$HOMEBREW_PREFIX` (Homebrew) |
| jenv | Loaded only when `command -v jenv` succeeds |
| Google Cloud SDK | Path via `$HOME`, sourced only if the file exists |
| `~/.local/bin` on PATH | XDG standard, added only if the directory exists |
| `b_dcls`, `b_graph` | Wrappers around `docker` and `git` — identical everywhere |
| `~/.zshrc.local` | Escape hatch for everything that is not portable |

## What is deliberately NOT here

| What | Why |
|---|---|
| Git configuration (`~/.gitconfig`, global ignore) | Carries identity and per-machine settings — stays outside the repo entirely |
| SSH (`~/.ssh/*`) | Keys and host configuration never leave the machine |
| `~/.zprofile` | `eval "$(/opt/homebrew/bin/brew shellenv)"` — an Apple Silicon path; an error on every login on Linux and Intel Macs. Stays a local file, outside the repo |
| `Brewfile` | `cask` installs `.app` bundles — `brew bundle` fails on Linux. Recreate it in a second: `brew bundle dump` |
| OMZ plugins `macos` and `brew` | **They have no OS guard** — they load anywhere, but `showfiles` is `defaults write com.apple.finder` and `ofd` calls `open`. Dead aliases on Linux |
| `/opt/homebrew/opt/openjdk@21/bin` on PATH | macOS-only path; Java is managed by jenv anyway |
| JetBrains Toolbox on PATH | `~/Library/...` on macOS vs `~/.local/share/...` on Linux |
| `~/.npmrc` | Contains the npm `_authToken` |
| `~/.kube/config`, `~/.config/gcloud` | Cluster and cloud credentials |
| `~/.yarnrc`, `~/.nuxtrc` | Autogenerated / trivial tool switches |
| `~/.oh-my-zsh/` | Someone else's repo, not your configuration — cloned by `install.sh` |

## Editing

Files in `$HOME` are symlinks, so editing `~/.zshrc` edits the file in the repo —
just commit it. One exception: `p10k configure` **replaces** `~/.p10k.zsh` with a
new file instead of writing through the symlink, so afterwards check `git status`
and copy the file back into `zsh/` if needed.
